# 公司元数据驱动的个股分析（强制规范）

> 用户 2026-09-12 明确要求：**"以后分析的信息源不能只来自那些文章，要从公司的元数据中分析得来。"**
> 本文档定义元数据采集口径、元数据→结论的推导规则、以及在晨报/日报里怎么写。
> 违规即返工：只有新闻归因、没有元数据支撑的个股分析一律不算完成。

## 0. 一条铁律

**先取元数据，再写结论。** 新闻（收评、涨停原因、板块文章）只能用作"催化剂/时点解释"，
不能充当分析主体。每只写进报告的股票，都必须有一段由元数据推导的基本面判定。

数据一次取全：`collect_stock_meta.py`（见 §2；本 profile 副本在 `~/.hermes/scripts/`，技能内副本在 `scripts/`）。取不到就写「未获取」，绝不编造。

## 1. 元数据 · 分析含义映射表

| 元数据字段 | 分析用途 | 判定规则 |
|-----------|---------|---------|
| 行业(EM2016)+主营(ORG_PROFILE/MAIN_BUSINESS) | 板块坐标系、题材归属 | 归入东财行业板块；主营决定是否真受益于题材（"蹭概念"看主营是否含该业务） |
| 总市值/流通市值 | 体量档位 | <50 亿=小市值易受资金炒作；50-300 亿=中盘；>500 亿=机构定价。流通市值/总市值=解禁与流通盘压力 |
| PE(TTM)、PE(动) | 估值水平 | 与同业中位数比：个股/同业中位 = 倍数。>2 倍标"估值显著高于同业"；亏损股 PE 记"亏损/不适用" |
| PB | 重资产/周期股主用 | 周期股用 PB 对照同业；PB>5 且 ROE<5% = 价格脱离盈利能力 |
| 营收同比、归母净利同比（近 3 期） | 成长与加速度 | 本期同比 > 上期同比 = 加速；净利增速显著高于营收 = 毛利/费用改善或非经常性因素 |
| 扣非净利同比 vs 归母同比 | 利润质量 | 扣非增速远低于归母 = 利润靠非经常性损益（补贴/处置），标"盈利质量弱" |
| 毛利率、净利率（近 3 期趋势） | 议价能力/成本压力 | 连续下滑=竞争恶化或成本上升；连续提升=产品结构/提价 |
| ROE | 资本回报 | <3% 属低效；>15% 属优秀；与 PB 交叉验证（高 PB 需高 ROE 支撑） |
| 资产负债率、流动比、速动比 | 财务风险 | 负债率>60% 且流动比<1 = 短期偿付压力，标风险 |
| 每股经营现金流 / 经营现金流营收比 | 盈利含金量 | 经营现金流长期低于净利 = 应收/存货占款，标"现金流弱" |
| 股东户数 + 环比 | 筹码集中度 | 户数环比下降=筹码集中（机构/大户吸筹）；大幅上升=散户涌入、筹码分散（多为高位派发信号） |
| 机构持仓家数 + 占流通比 | 定价主导者 | 机构家数多、占比高=机构定价；仅游资=情绪定价 |
| 最近公告（增发/回购/扩产/股权激励/减持/业绩） | 事件驱动导火索 | 优先引用最近 5 条公告标题作为上涨/下跌的具体原因（比新闻转述硬） |
| 同业中位数 PE/PB、市值相近可比公司 | 相对估值位置 | 优先用"市值相近可比公司(0.3~3 倍)"；板块前 10 大中若无相近体量，如实说明，不硬凑 |

## 2. 采集命令（唯一入口）

```bash
# 沪/深/北交所通用；北交所代码 92/43/83/87/88 开头自动识别（secid 0.xxxxxx / 腾讯 bj 前缀）
python3 ~/.hermes/scripts/collect_stock_meta.py 600584 002371 920212 \
        --json /tmp/meta_$(date +%Y%m%d).json
# 代码多时用文件：--file /tmp/codes.txt   或  cat codes.txt | python3 ... 
# 不稳定的增强源可跳过：--no-push2
```
- 单只约 2-5 s；4 只带同业约 10-20 s（内部 6 线程 + 多主机容灾）。**一次调用一条命令**，不要每只股票各调一次。
- 输出：DATA_TIMESTAMP + 每只一段「行业/主营/估值/行情/财务3期/指标3期/股东户数/机构持仓/公告/同业对比」。
- `--json` 落盘供程序化核对（字段同输出）。收盘后与盘前的差别只在行情字段。

数据源分层（脚本内已实现降级，勿手写）：
1. 腾讯 qt.gtimg.cn → 行情+PE(TTM)/PB/总市值（最稳）
2. 东财 F10 datacenter → 公司概况/利润表/主要指标/股东户数/十大流通股东
3. 东财公告 API → 最近公告
4. 东财 push2（stock/get、slist、clist）→ 行业名/地域板块/PE(动)/同业成分；**限流频繁**，
   脚本按 `push2 → push2delay → 82.push2` 轮换，`push2delay` 是限流时的主力兜底

## 3. 结论必须三选一，并给出依据

写每只股票时，先按元数据归类，再写文字：

1. **基本面驱动** —— 最近一期营收与净利同比双增且加速 + 毛利率稳定或提升 + PE 未显著高于同业中位（<1.5 倍）。
   写法示例：`2026中报营收195.27亿(+4.96%)、归母净利8.45亿(+79.41%)，毛利率15.15%较上期14.55%提升，
   PE(TTM)62.51低于半导体板块中位90.39，业绩改善是上涨主因`
2. **题材/资金驱动（无基本面支撑）** —— 营收或净利同比下滑/亏损/扣非为负 + 估值显著高于同业（>2 倍）
   + 无新公告。写法示例：`2025年报营收同比+0.42%、扣非同比-93.11%，PE(TTM)92倍高于电子板块中位64倍，
   上涨缺乏业绩支撑，属题材资金推动（风险提示：无基本面锚）`
3. **混合（预期先行）** —— 业绩在改善但估值已透支：`业绩改善已部分反映在股价中，PE 为同业中位 1.8 倍`

**禁止**：只写"受XX消息刺激涨停"；只写板块概念不写公司自身数据；把新闻标题当分析。

## 4. 强制输出模板（模块"大涨股分析/今日关注/自选股"共用）

```
### 名称（6位代码）涨幅 X%
【元数据】行业：半导体（主营：集成电路封装测试）| 总市值 1212 亿 | PE(TTM) 62.5（半导体板块中位 90.4，0.69 倍）
          PB 4.19（同业中位 11.12）| 最近一期 2026 中报：营收 195.27 亿(+4.96%)、归母 8.45 亿(+79.41%)、
          扣非 8.08 亿(+84.73%) | 毛利率 15.15%（上期 14.55%）| ROE 2.92% | 资产负债率 46.22%
          | 股东户数 84.75 万户（环比 +164.54%，筹码明显分散）| 机构 9 家占流通 30.35%
【事件】最近公告：9/11 股票期权激励授予结果；9/4 定增预案披露
【判定】基本面驱动：净利同比 +79.4% 且毛利率环比提升，估值低于行业中位；筹码分散需关注后续波动
```
要点：**每个数字都来自采集输出**；括号里给对标口径；最后一句是判定+依据，不是买卖建议。

## 5. 硬规则与红线

1. 报告里出现的每只股票，都必须跑过 `collect_stock_meta.py`；未跑=分析不合格。
2. 字段缺失写「未获取」；同业取不到时写「同业中位数未获取」，并退化为纵向（自身历史期）对比。
3. 亏损/负 PE 必须写"亏损/不适用"，不得当"低估值"；此时用 PB/PS 口径。
4. 港股/美股计价币种不同（HKD/USD），**禁止直接把 PE/PB 与 A 股同业混比**，要分别标注币种。
5. 剔除仙股/垃圾股时给元数据依据（总市值、换手），不要凭感觉。
6. 新闻、公司公告、元数据三类来源都要标注（据东方财富 F10/据腾讯行情/据公司公告）。
7. 股东户数环比大幅上升（>50%）时，必须提示"筹码分散/散户接盘"风险；机构占比骤降同样提示。

## 6. 已知坑（2026-09-12 实测）

- `RPT_F10_EH_HOLDERNUM` / `RPT_F10_EH_FREEHOLDERS` **没有 REPORT_DATE 排序列**，带
  `sortColumns=REPORT_DATE` 返回 `code 9501 报表配置不存在/排序列不存在` → 必须用 `sortColumns=END_DATE`。
  同理 `RPT_F10_BASIC_ORGINFO` 完全不能带排序列参数。
- `RPT_F10_FINANCE_MAINFINADATA` 的营收/净利字段恒为 None → 营收净利取 `GINCOME`，MAINFINADATA 只补
  `XSMLL`毛利率 / `XSJLL`净利率 / `ROEJQ` ROE / `ZCFZL` 资产负债率 / `LD`流动比 / `SD`速动比 / `MGJYXJJE`每股经营现金流。
- 东财 push2 限流：TLS 成功但返回空或 `RemoteDisconnected`。**curl 通常仍能通**（urllib 被拒时）；
  主力兜底是 `push2delay.eastmoney.com`（延时行情，估值/同业对比完全够用）。
- 行业板块名录接口 `fs=m:90+t:2` 单页最多 100 条（total≈496），必须 `pn=1..6&pz=100` 翻页，
  否则只有前 100 个板块（会漏掉"半导体""航运"等，导致同业对比匹配到过宽的"电子"板块）。
- `slist/get` 的 `diff` 是 dict（`{"0":{...}}`）而 `clist/get` 是 list → 解析要归一化。
- 腾讯字段索引：f[38] 换手、f[39] PE(TTM)、f[45] 总市值(亿)、f[46] PB（脚本已写死，勿手改）。
- 盘前运行：行情字段是最近收盘价，财务/股东/公告字段不受影响；财报刚披露时 PE(TTM) 会跳变，
  写"业绩驱动"前先核对最新报告期披露日（NOTICE_DATE）。
- 同业中位数是"板块前 N 大市值"口径：小市值/北交所个股的板块内样本多为巨头，
  必须改用"市值相近可比公司(0.3~3 倍)"或如实说明无相近样本。

## 7. 两张常用附表：新股细分领域、分红与股息率

### 7.1 未上市新股的"细分领域"（模块五表格必填）

东财搜索 jsonp 对新股名称的**相关性极差**（搜"某某 新股"返回当日大盘文章），不要用它凑。
正确做法：对申购中的新股代码直接跑 `collect_stock_meta.py <代码>` —— **F10 ORGINFO 在上市前就能取到**
行业/主营/省份/员工/实控人/最近一期 ROE；行情类字段（PE/PB/市值）为空属正常。把"主营"压成一句话填表，
确实取不到就写"—"。

### 7.2 中期分红 / 年报分红与股息率

报表 `RPT_SHAREBONUS_DET`（`sortColumns=REPORT_DATE` 可用，pageSize=30）：
- `PRETAX_BONUS_RMB` = 每 10 股税前派息（元）
- `REPORT_DATE` **06-30=中期分配、12-31=年报分配** —— 写"中期分红"必须看 REPORT_DATE，
  不要按年份把中期方案当成年度分红
- `ASSIGN_PROGRESS`（预披露 / 董事会决议通过 / 股东大会决议通过 / 实施分配）、`PLAN_NOTICE_DATE`、`EX_DIVIDEND_DATE`
- 股息率 = `PRETAX_BONUS_RMB / 10 ÷ 最新收盘价`；只反映该期一次分配，**必须标注"未年化"**，
  不得作为全年股息率或对未来分红的预测

### 7.3 派生指标一律脚本计算

PE/PB 相对同业倍数、股息率、同比加速等，全部在生成脚本里用真实字段算完再写进文本；
手算的倍数一旦与数据源口径不符，用户会按错误倍数做判断。
